# Stage 5 — Paper, `morphstack` CLI release, Crumb integration, and launch

**Labels:** `tracking`, `stage-5`, `release`, `paper`, `crumb`

## Outcome

Deliver three things together:
1. an arXiv preprint, prepared so it can go straight to a peer-reviewed venue;
2. a cross-platform `morphstack` CLI distributed the same way as Crumb;
3. integration with Crumb in both directions, so the two projects improve together.

## Scope

### Paper
- [ ] Structure as in plan section 27, written in LaTeX in `paper/`. Every figure and table must be regenerated by `morphstack report`, with no numbers copied in by hand.
- [ ] Artifact package (Docker image, scripts, and a pinned dataset of traces) built to the ACM Artifact Evaluation checklist, aiming for the *Available*, *Functional*, and *Reproduced* badges.
- [ ] arXiv: primary category **cs.PL**, cross-listed to **cs.OS** and **cs.PF**, and **cs.DS** if the MTS theory turns out substantial. A first-time submitter in cs needs an endorsement, so arrange one early.
- [ ] Candidate peer-reviewed venues: PLDI, OOPSLA, ASPLOS, ISMM (memory management fits closely), VEE, or MPLR. Choose from the strength of the results. A negative result fits ISMM or a workshop.
- [ ] Mirror the paper on research.elixpo.com.

### CLI (`morphstack-cli`)
```text
morphstack gen       <workload>        generate synthetic traces
morphstack capture   <source>          convert Tokio/Go/asyncio traces
morphstack trace     validate|stats
morphstack sim       --policy ...      price a policy on a trace
morphstack oracle    trace             hindsight-optimal schedule + cost
morphstack compare   trace             all policies vs oracle, regret table
morphstack calibrate                   measure cost-model params on this machine
morphstack bench     (Linux)           run real-runtime benchmarks
morphstack report    --all             regenerate every paper figure
morphstack explain   trace             agentic: narrate why/when the oracle switched (crumb-harness)
```

### Distribution (same pipeline as Crumb)
- [ ] `install.sh` and `install.ps1`, a Homebrew formula, and GitHub Releases with Sigstore signatures. Reuse Crumb's `release.yml` and `release-gate.yml`.
- [ ] Debian package through the same `debian/` + mentors workflow as Crumb. **Do this early:** freeze dependency versions at what Debian already packages, as Crumb already does by holding rusqlite at 0.40.
- [ ] Publish the crates on crates.io.

### Crumb integration (both directions)
- [ ] **MorphStack → Crumb:** `morphstack-agent` depends on `crumb-harness` behind a cargo feature and uses it for:
  - `morphstack explain`, which turns oracle and policy decisions into a readable narrative;
  - a literature-watch agent that re-runs the SLR queries and flags new related work;
  - an experiment-runner agent that proposes parameter sweeps, runs them through the CLI, and summarizes regret changes.

  The core binary must work fully **without** this feature, because the paper's results must not depend on an LLM.
- [ ] **Crumb → MorphStack:** publish MorphStack as a Crumb marketplace package (a *command adapter* plus an *instruction skill*, following the package classes in epic elixpo/crumb.elixpo#148). A user can then ask Crumb to *"compare stack policies on this trace"* and Crumb installs and runs the CLI.
- [ ] Shared conventions with Crumb: provenance and audit logs for agentic runs, and the same governance and trademark files.

### Launch
- [ ] Website `<name>.elixpo.com` with docs, an interactive policy and oracle visualizer that runs the simulator compiled to WASM, and paper links.
- [ ] Listings on elixpo.com and research.elixpo.com.
- [ ] `CHANGELOG`, `v1.0.0` tag, and an announcement post.

## Exit criteria
- The preprint is live on arXiv, the artifact is public, and a reviewer can reproduce every figure with one command.
- The CLI installs through `install.sh`, `install.ps1`, Homebrew, and the Debian/APT repository on Linux, macOS, and Windows.
- `crumb skill run elixpo/morphstack -- compare <trace>` works end to end.
